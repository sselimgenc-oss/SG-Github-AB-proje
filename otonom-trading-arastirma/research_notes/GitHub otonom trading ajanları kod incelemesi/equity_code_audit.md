## 1. Does the agent itself research and decide, and does it place/close real or paper broker orders (which SDK calls, which file/function)?

### Takeaway
Only two of the repos have working order-placement code reachable from an agent loop: AgenticTrading (a demo `ExecutionAgent`, Alpaca paper by default) and NightWatcher-V2 (Alpaca via an MCP Worker, paper by default, but with rule-based rather than LLM decisions). The famous frameworks (TradingAgents, ai-hedge-fund, FinRobot, TradingAgents-CN) stop at a rating, a report or a simulated book. HKUDS/AI-Trader is a platform, not an agent. TradingAgents PR #281 (Alpaca paper broker) is NOT merged into main.

### Cited Findings

**TauricResearch/TradingAgents (main, 2026-11-04, one squashed commit "announce Trading-R1 official release")**
- No broker/order code on main: `grep -ri alpaca` over the tree returns nothing; the only "broker" hits are symbol-format comments (`tradingagents/dataflows/symbols.py`) and `tradingagents/portfolio.py:9` ("Broker-neutral by construction ... nothing here implies a venue or an execution path"). README line 74: "designed for research purposes ... not intended as financial, investment, or trading advice."
- Decision pipeline is fully LLM-driven and self-gathering: four analysts (market/social/news/fundamentals) call data tools (yfinance, SEC EDGAR, FRED, Polymarket) with up to `max_tool_rounds=20` (`tradingagents/default_config.py`), then Bull/Bear debate -> Research Manager -> Trader -> Aggressive/Conservative/Neutral risk debate -> Portfolio Manager (`tradingagents/graph/setup.py`, `graph/conditional_logic.py`). The user supplies only ticker and date.
- Output is a typed rating: `PortfolioRating` Buy/Overweight/Hold/Underweight/Sell plus optional `price_target`, `time_horizon` (`tradingagents/agents/schemas.py`); the Trader proposal has optional `entry_price`, `stop_loss`, `position_sizing` (schemas.py:172 for `stop_loss`). These are text for a human, nothing consumes them as orders.
- Adaptation: a markdown "memory log" is settled against realized returns (holding period default 5 trading days, benchmark alpha) and "lessons from prior decisions" are fed to the Portfolio Manager (`tradingagents/memory/`, `agents/managers/portfolio_manager.py:35-38`, `memory/reflection.py:63` is an LLM call). `tradingagents/backtest.py` (`run_backtest`, line 143) scores ratings over a date grid; it is a rating scorer, not an order simulator.
- PR #281 (author-claimed Alpaca paper broker): fetched via `git fetch --depth 1 origin pull/281/head:pr281`; it exists as a branch with 181 changed files. Not merged: main has no `tradingagents/brokers/` directory and no alpaca string anywhere. I could not read the PR's open/closed state through the API (403: "GitHub access to this repository is not enabled"), so "unmerged" is inferred from main's content, not from PR metadata. PR head commit is `16192cd` dated 2025-11-17 with author "Claude" and message "Complete production-ready sprint". Contents of the PR branch: `tradingagents/brokers/alpaca_broker.py` (raw `requests` to `https://paper-api.alpaca.markets` / live URL, `submit_order` at line 401, `paper_trading=True` default, reads `ALPACA_API_KEY`/`ALPACA_SECRET_KEY`), `brokers/base.py` (order/position models), `examples/tradingagents_with_alpaca.py`, `examples/paper_trading_alpaca.py`. In the example, `ta.propagate(ticker, trade_date)` output is mapped to market buy/sell by caller script code (the example only sells if a position exists; the example has no hard size limit that I found). The PR also bundles dozens of AI-generated status documents (ANALYSIS_SUMMARY.md, COMPLETE_IMPLEMENTATION_SUMMARY.md, etc.), consistent with it not being a reviewed maintainer change.

**hsliuping/TradingAgents-CN (v3.0.0 community edition, 2026-09-22)**
- A-share (plus HK/US) multi-agent research web app: FastAPI backend + Vue frontend + MongoDB/Redis. Analyst set adds china_market, sector and index analysts (`tradingagents/agents/analysts/`), debate and risk judge (`tradingagents/graph/setup.py` nodes at lines 274-281, `Risk Judge` -> END at line 362); default debate/risk rounds 1/1 (`tradingagents/default_config.py:17-18`).
- No external broker SDK calls: greps for `submit_order|place_order|create_order|ib_insync|easytrader|alpaca` finds only the paper endpoint and an xtquant (QMT) data adapter. `app/services/data_sources/qmt_adapter.py:331` calls `trader.query_stock_positions(account)` (read-only position import); no `order_stock` call exists.
- "Paper trading" is a user-driven simulator: `POST /order` in `app/routers/paper.py:538` (`place_order`) fills at last price or a user-specified price validated against the day's high/low and writes to Mongo (`paper_trades` collection, `app/services/trade_review_service.py:242`). It requires an authenticated human (`Depends(get_current_user)`), and no agent code path calls it (the only agent-side tool is the read-only `core/tools/implementations/assistant_ops/paper_trading_status.py`). AI is used afterwards for trade review (`trade_review_service.py`).
- `app/services/stop_gain_alert_service.py` scans user-set take-profit levels and only sends notifications.

**virattt/ai-hedge-fund (v2.7.2 package `aihf`, 2026-11-09)** -- note this is a ground-up rewrite; the older README-era agents.py CLI is gone from this tree.
- README line 7: "the system does not actually make any trades"; `VISION.md` header: "not intended for real trading". No alpaca/ibkr/broker SDK references anywhere (grep over *.py/*.md/*.toml: only the internal `hedge_fund/brokers/` package).
- Broker layer is internal: `Broker` protocol (`hedge_fund/brokers/protocol.py:34`, `place_order(self, order) -> Fill`), `SimBroker` (backtest), `PaperBroker` (same book persisted to `broker.json`, `hedge_fund/brokers/paper.py`). Fills are complete, at the execution session's close, with a half-spread + commission cost model (`brokers/costs.py`, defaults spread 5 bps, $0.005/share in `fund/example.yaml`). `protocol.py` docstring: "a live broker implements the same three methods later"; ROADMAP says live is "a broker away".
- Loop closure inside the simulator: `advance()` (`hedge_fund/pipeline/session.py:132`) reconciles ledger vs broker, executes the pending decision at T+1, marks, and runs `assess_fund` if it is a rebalance session; `aihf paper run <name>` is an unattended daemon that sleeps until the next session is due (`hedge_fund/paper/runner.py`, `spawn_runner` line 243). The TUI adds a human approval step before a manual run (`hedge_fund/tui/paper.py:352`), but the daemon path has none.
- Who decides: user supplies a mandate (which investor personas, weights, cadence, risk limits) and a ticker universe (`fund/example.yaml`: "no tickers here ... universe is fixed when you backtest or deploy"). LLM personas (Graham/Buffett/Munger/Lynch/Druckenmiller) each emit a bullish/neutral/bearish Signal per ticker (`hedge_fund/signals/llm_agent.py`), which deterministic code blends into target weights (`pipeline/stages.py:assess_fund`, lines 90-91 loop `model.predict` per ticker per model). The LLM does not size or place orders.
- Adaptation: none found in the LLM path (prompt cache keyed on prompt hash, `llm_agent.py:85-91`); the "scorecard" re-weights strategies/models from ledger history (`hedge_fund/scorecard/`, `session.py` `allocation` param) -- deterministic, not LLM self-modification.

## 2. Who owns exits, and are there hard risk limits in code?

### Takeaway
Hard, LLM-independent risk code exists in ai-hedge-fund (rich portfolio limits + drawdown stop-out), NightWatcher-V2 (Worker policy engine + fixed TP/SL) and AgenticTrading's disabled Robinhood path ($25 default per-order cap). TradingAgents, TradingAgents-CN, FinRobot and AI-Trader have none, because they place no orders; AgenticTrading's active demo has none.

### Cited Findings
- TradingAgents: exits are not implemented at all; the LLM only suggests an optional `stop_loss` price and a free-text `position_sizing` (`tradingagents/agents/schemas.py:172`); `portfolio.py` is optional context (cash, positions) given to agents so they can distinguish adding vs opening. No limits in code. The `_coerce_optional_float` helper drops "15%"-style stops rather than turning them into prices (schemas.py docstring), a validation guard but not a risk control.
- ai-hedge-fund: exits are deterministic rebalancing, not LLM. Target weights from blended signals are clamped by `apply_limits` (`hedge_fund/risk/limits.py:127`): per-name cap, net cap, then sector, beta, volatility, drawdown-halving and gross caps; docstring: "Everything here is deterministic arithmetic -- the LLM's influence over the book ends at the Signal". `RiskLimits` fields: `max_position_pct`, `max_gross_exposure`, `max_net_exposure`, `max_drawdown_pct`, `halve_drawdown_pct`, `max_adv_pct`, `max_beta`, `max_sector_pct`, `max_volatility` (limits.py:37-72). Drawdown stop-out: `advance()` sells everything and stays in cash when drawdown >= `max_drawdown_pct` (`session.py:185`, `stop_out_decision`). Kill switch: `FundHalted` (session.py:57), any failure in a tick halts the fund (ROADMAP). LLM parse failure abstains (value 0.0) rather than defaulting to a trade (`signals/llm_agent.py:18`). Caveat: limits are per `FundSpec`; the example sets `max_drawdown_pct: 0.20` but many are commented-out optional.
- NightWatcher-V2: exits are deterministic in `agent.mjs`: `take_profit_pct: 8`, `stop_loss_pct: 4` (crypto 10/5), polled every `analyst_interval_ms: 120_000` (2 min) in the Node client, then `positions-close` (agent.mjs:509, 646-647). Note these are client-side polling, not broker-side bracket orders, so they depend on the Node process being alive. Server-side policy engine `PolicyEngine.evaluate` (`src/policy/engine.ts:48`) applies kill switch, cooldown, daily loss limit, trading hours, symbol filters, order type, notional limit, position size, open-positions limit, short selling, buying power; defaults from env: `max_position_pct_equity` 0.10, `max_open_positions` 10, `max_notional_per_trade` 5000, `max_daily_loss_pct` 0.02 (`src/policy/config.ts:102-106`). Exception: the `positions-close` tool "bypasses preview/submit but checks kill switch" (`src/mcp/agent.ts:354`). The agent's own `max_position_value` 2000 / `max_positions` 3 / 20% of cash apply client-side.
- AgenticTrading: active demo `execute_orders` has no limit, the LLM picks qty (`execution_agent.py:181`); the disabled Robinhood path has `_risk_gate_orders` (`robinhood_live_service.py:423`): per-order USD cap (`DEFAULT_MAX_ORDER_USD = 25.0`, line 54, env-overridable and read per call), a `MAX_ORDER_SHARES = 10000` ceiling (`infrastructure/llm/validator.py:308`), idempotency cache, a pre-trade review gate, a Dow-30 symbol whitelist (`allowed_symbols: DJIA_30`) and a kill switch. Moot while `ROBINHOOD_LIVE_ENABLED = False`.
- FinRobot / TradingAgents-CN / AI-Trader: no order path, so no exit or limit logic (AI-Trader only charges a flat 0.1% fee in its ledger, `fees.py:5`).

### Inferences
- "Exit owned by deterministic code" is true for ai-hedge-fund and NightWatcher-V2; nowhere did I find an LLM that autonomously manages exits against a real or paper broker with code-level guardrails except the AgenticTrading demo, which lacks guardrails.
- NightWatcher's client-side TP/SL polling (2 min) plus a bypass in `positions-close` means protection is weaker than a broker-side bracket order would give.

### Gaps
- Did not test whether ai-hedge-fund's TUI forces risk limits to be set (a mandate may omit most optional limits).
- NightWatcher Worker's behavior on duplicate orders/restarts not tested.

## 3. API-key handling and red flags (obfuscation, eval/base64, suspicious hosts, install scripts, typosquats)

### Takeaway
No malware-pattern code in any cloned repo (no obfuscation, no `eval` of remote data, no install hooks, deps look canonical). The real security issues are design weaknesses: NightWatcher-V2's unauthenticated local key-writing endpoint with wildcard CORS and its apparently unauthenticated MCP Worker, AI-Trader's pull-instructions-from-remote-host agent onboarding, and optional telemetry/third-party calls in TradingAgents.

### Cited Findings
- TradingAgents: keys read from env/.env via per-provider map (`tradingagents/llm_clients/api_key_env.py`); CLI prompts for missing keys. Network use limited to data vendors (Yahoo, SEC EDGAR with User-Agent, FRED, Polymarket, Alpha Vantage), LLM providers, an optional "Sign in with ChatGPT" OAuth (PKCE, loopback redirect, tokens in `~/.tradingagents` owner-only file; hosts `auth.openai.com`, `api.openai.com`; `llm_clients/chatgpt_auth.py:29-34`), an update check to the GitHub releases API and an announcements fetch from `https://api.tauric.ai/v1/announcements` (`cli/updates.py:30-31`, a phone-home-style call but a GET with no payload), and optional social-post screening to `https://api.typesafe.ai` only when `TYPESAFE_API_KEY` is set, which posts StockTwits/Reddit text there (`agents/post_screen.py:27, 87`). `base64` use is only PKCE/JWT encoding. `pyproject.toml` deps are mainstream (langchain/langgraph/yfinance/pandas); no install scripts beyond a console entry point. The PR #281 branch adds `tradingagents.security` and a `.chainlit` file, but it is not in main.
- ai-hedge-fund: keys saved to `~/.hedge-fund/.env` with chmod 0600 (`hedge_fund/tui/keys.py:63`); shell env wins. It can accept an `X402_WALLET_PRIVATE_KEY` (a Base wallet private key) to pay for Financial Datasets calls via x402 (`hedge_fund/data/wallet.py:17`, `Account.from_key` line ~51; optional extra `aihf[x402]`). ## 4. LLM calls per decision and rough cost per ticker-decision (mid-priced model)

### Takeaway
TradingAgents costs the most per ticker (~15-25 calls, tens of thousands of tokens each); ai-hedge-fund is ~1 short call per persona per ticker (3-5 calls) and cached; AgenticTrading and NightWatcher are about 1 call per cycle or none. Figures are my estimates from graph structure with stated assumptions, not measurements.

### Cited Findings
Assumptions: a "mid-priced" model at about $3 per million input tokens and $15 per million output tokens (Claude-Sonnet-class); a cheaper mini model at about $0.30/$1.50. Token volumes are my guesses; tool outputs (price tables, news, filings) dominate input.

- TradingAgents (defaults `max_debate_rounds=1`, `max_risk_discuss_rounds=1`, `default_config.py`): analysts 4 agents, each a ReAct loop of typically 2-5 model turns (cap 20 tool rounds) = ~8-20 calls; bull + bear = 2 calls (1 round each; `count >= 2*rounds`); Research Manager 1 (deep model); Trader 1; risk debate 3 calls (aggressive, conservative, neutral; `count >= 3*rounds`); Portfolio Manager 1 (deep model); plus 1 reflection call when a past decision is settled (`memory/reflection.py:63`). Total about 17-30 calls. Estimated ~150-300k input tokens (re-sent tool outputs and reports) and ~20-30k output tokens, i.e. roughly $0.7-1.4 per ticker-decision on a $3/$15 model, or ~$0.08-0.15 on a mini-class model. A secondary source quoted $0.30-0.50 per single-ticker analysis at GPT-5 rates in earlier notes (see `llm_equity_frameworks.md`, via Pinggy) which is consistent with the lower end. Defaults in config name placeholder tier names `gpt-6-sol` / `gpt-6-luna` (`default_config.py`), so real pricing depends on the model you map to. Also a rate limit note: Alpha Vantage free tier 25 calls/day applies only if you select that vendor; default vendor is yfinance/SEC EDGAR (no key).
- TradingAgents-CN: same topology with extra analysts (china_market, sector, index) -> ~20-35 calls; default model in bootstrap config is dashscope qwen-turbo/qwen-plus (cheap), so cost is typically ~$0.02-0.15 per run on those, ~$1-2 on a Sonnet-class model. (Structure from `tradingagents/graph/setup.py`; costs are estimates.)
- ai-hedge-fund v2: one call per (strategy persona x ticker) per rebalance session (`pipeline/stages.py:90-91`); `deep-value` pod = 3 personas, so 3 calls/ticker/rebalance, each a compact fundamentals snapshot prompt (maybe 2-4k in, 0.5k out) at `max_tokens=4096` (`llm/client.py:228`), with an on-disk prompt cache so identical snapshots cost nothing (`llm_agent.py:85-91`). Estimate $0.03-0.06 per ticker-rebalance for 3 personas on a $3/$15 model; near zero between rebalances (daily/weekly/monthly cadence) because the pipeline only calls analysts on rebalance sessions (`session.py:195 is_rebalance_session`).
- FinRobot V2: 13-chapter report, 8 agent roles, retries and audit -> on the order of 10-25 calls per ticker report (my estimate from the agent/pipeline list), $0.5-2 on a mid-priced model; numbers come from deterministic operators, not the LLM. Backtest tuner: 3 LLM iterations per strategy.
- AI-Trader: no LLM calls in repo (external agents bring their own).
- AgenticTrading: Robinhood path (disabled): 1 call per run across the whole Dow-30 whitelist (`_llm_decision`), `max_tokens=2000`, cheap (~$0.02-0.05 per run). Demo `ExecutionAgent`: 1 agent run per cycle with 1-3 tool round trips.
- NightWatcher-V2 as shipped: 0 LLM calls in the agent loop (`agent.mjs:273`); optional Worker `symbol-analyze` = 1 call per symbol.

### Inferences
- At a 5-minute cadence on 20 tickers, TradingAgents-style pipelines would cost hundreds of dollars per day on a mid-priced model; they are practical only for daily or lower-frequency decisions on a short watchlist. ai-hedge-fund's cache + rebalance-only calls is the cheapest of the LLM-in-the-loop designs.

### Gaps
- No token counts were measured (no code run, by instruction); all costs are estimates from graph structure and assumed prompt sizes.

## 6. Autonomy classification (L0-L5) with reasoning against the framework's criteria

### Takeaway
No repo reaches L4 in a verified way; none is credibly L3 on real-money equities with guardrails. Best single-line assignments: TradingAgents L2 (adaptive memory but no orders), ai-hedge-fund L2 (L3 on a simulator), TradingAgents-CN L2, FinRobot L2, AI-Trader L0-L1 (infrastructure), AgenticTrading L2 (demo L3 with random alpha), NightWatcher-V2 L3 plumbing with L1 decision logic, Infinite Bagholder unrated.

### Cited Findings (criteria from `advisor_framework.md` section 1)
- Criteria: decision origin / loop closure / info gathering / exit ownership / adaptation / scope freedom.
- TradingAgents: origin LLM (agents decide rating; user gives ticker+date); loop closure NO (no order call); gathers its own data YES; exit ownership none (suggested stop only); adaptation YES (memory log of realized returns/alpha injected into Portfolio Manager); scope: long/short rating across any listed ticker, user picks tickers. -> **L2** (as shipped). Via PR #281's caller-side script it would reach L3-without-risk-limits, but PR is not in main.
- TradingAgents-CN: origin LLM; loop closure NO (human-placed simulated orders); gathers data YES (AkShare/Tushare/Finnhub); exit none; adaptation memory (chromadb/mem0-style, `tradingagents/agents/utils/memory.py`, `reflect_and_remember` in `graph/trading_graph.py:1716`); -> **L2**.
- ai-hedge-fund v2: origin split: user picks personas/universe, LLM emits per-ticker conviction, deterministic code converts to weights; loop closure only to its own simulated broker (unattended `paper run` daemon); exits deterministic (rebalance + drawdown stop-out); adaptation: scorecard re-weighting (deterministic), no prompt/self-rewrite; scope: user-fixed universe. -> **L2** for real trading, **L3-on-simulator** (closest to "closed loop" with proper risk code).
- FinRobot: origin LLM narrative over deterministic numbers; loop closure NO; backtest tuner only. -> **L2** (L1 for the BackTrader parameter-tuning module).
- AI-Trader: no decision code; ledger of externally submitted signals; the repo is infrastructure for other agents. -> **L0/L1** by itself (record the external agents' own level separately); real orders never placed by this repo.
- AgenticTrading: shipping dashboard backtests with LLM trading agents defined by user prompts -> **L2**; orchestration demo has an LLM that does place Alpaca paper orders but its alpha input is `random.uniform` -> demonstrates **L3 plumbing without an autonomous research layer**; Robinhood real-money path off.
- NightWatcher-V2: loop closed (scheduled, places and closes Alpaca orders without human click, paper default, kill switch, policy engine); decision origin deterministic sentiment thresholds and fixed TP/SL; LLM available but unused by `agent.mjs`; adaptation: Worker has memory tables and "summarizeLearnedRules" (`src/mcp/agent.ts` imports it) but not wired in the default agent (not verified end-to-end). -> **L3 loop, decision logic at L1 as shipped**; L3-L4 only if the Worker's LLM tools are connected.
- Infinite Bagholder: forum claims describe L3 (autonomous agent + news loops, Alpaca paper/live, code-level guardrails: penny-stock block, stop-loss, allocation caps) but unverified -> **unrated; claim = L3**.

### Inferences
- Matches the earlier catalog's view (`llm_equity_frameworks.md`): research frameworks are L2, and the closest closed-loop projects are small, new, single-author, and (for NightWatcher) rule-based under an "autonomous multi-agent" label.
- Marketing vs code gap: NightWatcher's README ("Validates with LLMs") and article claim LLM validation that is not in the default agent path; AgenticTrading's README-level "LLM-powered trading agents" is mostly backtest/leaderboard infrastructure.

### Gaps
- I did not verify the performance claims of any project (out of scope for this code audit); see `llm_equity_frameworks.md` for reproduction/benchmark evidence.
- ygwyg/NIGHTWATCHER-V2 and Infinite Bagholder not examined as code.
